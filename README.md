# FILTR

Десктопное приложение для сортировки музыки. Две папки рядом, компактный плеер снизу, теги и перенос файлов между каталогами.

## Стек

- Electron + electron-vite
- React + TypeScript + Vite
- Tailwind CSS
- wavesurfer.js
- lucide-react
- music-metadata
- node-id3

## Запуск

```bash
npm install
npm run dev
```

`npm run dev` и `npm start` открывают окно Electron. Файловая система доступна только главному процессу; рендерер ходит к ней через preload.

Не открывайте адрес рендерера в Chrome или Firefox: без preload браузер не получает `window.api`. Если такая вкладка всё же открылась, в ней будет отказ, а интерфейс останется в окне FILTR.

Другие команды:

```bash
npm test
npm run typecheck
npm run lint
npm run build
```

Dev-сервер рендерера слушает `127.0.0.1:45873`.

## Как пользоваться

1. В каждой колонке нажмите кнопку с папкой и выберите каталог. Эти пути запоминаются и открываются снова при следующем запуске.
2. Папки стоят сверху списка. Клик открывает вложенный каталог, пункт `..` возвращает на уровень выше, но не выходит за выбранный корень.
3. При открытии папки файлы встают по имени. Переименование и энерготег меняют строку на месте и не пересортировывают список, пока папку не откроют снова. Одинаковые имена без расширения и точные копии подсвечены бледно-красным.
4. Клик по треку в любой колонке загружает его в нижний плеер.
5. Кнопки PREPARTY, MID, PRIME, AFTERPARTY и END дописывают или снимают тег в имени файла. Старый тег PARTY при переименовании и синхронизации становится PRIME. Теги всегда стоят в начале, без дублей и в этом порядке: `[PREPARTY][END] Название.mp3`. Это имя без расширения сразу записывается в ID3 Title. Кнопка с картинкой в правой колонке вписывает обложку по первому тегу во все аудиофайлы открытой папки и её подпапок. Соседняя кнопка записывает текущие имена файлов в ID3 Title.
6. Стрелка на строке переносит файл в текущую папку соседней панели. Трек можно перетащить в другую колонку: он встаёт в конец того списка. Сброс на строку вложенной папки кладёт файл внутрь неё. Уже открытый порядок списков не перемешивается.
7. Карандаш меняет имя файла и теги Title, Artist, Genre, BPM. Запись тегов работает для MP3 и WAV. Если этот трек уже играет, плеер не перезагружает его.
8. Корзина убирает трек из списка. Внизу появляется «Трек удален» и «Отмена» на 5 секунд. Без отмены файл уходит в системную корзину.
9. Пробел — пауза. Стрелки влево и вправо — предыдущий и следующий трек в активной панели.

Рядом с именем видны Artist, Title, Genre, BPM и Key, если они есть в файле.

Поддерживаемые расширения: mp3, wav, flac, aiff, aif, ogg, opus, m4a, aac, wma, alac, caf.

## Безопасность IPC

Рендерер не получает Node.js. `contextIsolation` включён, `nodeIntegration` выключен, preload работает в sandbox. В `window.api` только методы выбранных папок:

- `selectDirectory(side)` — системный диалог, корень панели
- `listDirectory(side)` — папки и аудиофайлы текущего каталога
- `enterDirectory(side, path)` и `goUp(side)` — переход внутри корня
- `restoreDirectory(side, root, current)` — открыть запомненные пути
- `moveFile(path, side, directory?)` — перенос в текущую папку соседней панели или в указанную папку внутри открытого корня
- `renameFile(path, name)` — новое имя в той же папке
- `writeTags(path, tags)` — запись ID3 в MP3 или WAV
- `trashFile(path)` — переместить аудиофайл в системную корзину

Main принимает вызовы только от своего окна. Путь проверяется через `realpath`, чтобы симлинк или соседний каталог с похожим префиксом (`/music` и `/music-evil`) не вышли за выбранную папку. Имя файла не может содержать разделители пути.

Плеер читает трек через `read-audio-file` целиком в память и отдаёт wavesurfer ссылку `blob:`. Файл на диске после чтения закрыт, поэтому переименование и запись ID3 не упираются в блокировку Chromium. Запрос вне открытых папок или с неаудио-расширением получает отказ.
